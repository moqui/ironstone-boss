# Seam review: plan → make → stock → cost (Oct 28, 2026)

Second-phase handoff review across the Products, Manufacturing, Warehouse, Accounting, Purchasing and Projects designs and the crosscut. Paths: `cc:` = `runtime/component/mr-boss/plan/design-crosscut.md`; `mfg:`, `prd:`, `wh:`, `acc:`, `pur:`, `prj:` = `design-manufacturing.md`, `design-products.md`, `design-warehouse.md`, `design-accounting.md`, `design-purchasing.md`, `design-projects.md` in the same directory. `M:` = `runtime/component/mr-mantle/`. Mantle was read as active XML (comments stripped); line numbers are in the real files. "By reading" means the code path was traced but not run. 3p paths are under `~/work/moquiwork/3p_other/`.

Short names for the existing Mantle hooks used below:
- **IssueHook**: SECA `AssetIssuanceGlPost` (`M:service/AccountingLedger.secas.xml:78`) → `AssetAutoPostServices.post#AssetIssuance` (`M:service/mantle/ledger/AssetAutoPostServices.xml:206`). It posts Dr `GatWipInventory`, Cr `GatInventory` at `Asset.acquireCost` only when `WorkEffort.ownerPartyId == Asset.ownerPartyId`, otherwise Dr `GatCogs` (:264). On a `ShpTpTransfer` shipment it uses `AssetTypeGlAccount.transferGlAccountId` if one is configured (:304).
- **ReIssueHook**: SECA `AssetIssuanceGlRePost` (`AccountingLedger.secas.xml:81`) runs on every `update#AssetIssuance`. `repost#AssetIssuance` (`AssetAutoPostServices.xml:388`, :407) calls `unpost#AcctgTrans` and **deletes** the original transaction, then posts again dated the original `issuedDate`.
- **ReceiptHook**: SECA `AssetReceiptGlPost` (:74) → `post#AssetReceipt` (`AssetAutoPostServices.xml:19`). It posts Dr `GatInventory`, Cr `GatWipInventory` when `AssetReceipt.workEffortId` is set, otherwise Cr `GatUnreceivedInventory` (:73). For a `ShpTpTransfer`, `transferGlAccountId` overrides that credit (:99). If `Asset.acquireCost` is null it records `AtrNoAcquireCost` and posts nothing (:43).
- **VarianceHook**: SECA `AssetDetailPhysicalVarianceGlPost` (:89) → `post#PhysicalInventoryVariance` (:754). It posts only when `AssetDetail.physicalInventoryId` is set, to `GatInvShrinkage` or `GatInvFound` by sign (:818), at `asset.acquireCost`, dated `physicalInventoryDate`. It allows one transaction per asset per PhysicalInventory; any later one is skipped silently (:784).
- **AutoReserve**: SECA `AssetStatusAvailableReservations` (`M:service/ProductAsset.secas.xml:16`) → `reserve#IncreasedAsset` whenever an asset becomes `AstAvailable`.
