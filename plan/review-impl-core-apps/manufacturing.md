## Questions for the user

1. **Cancel after postings (I-MFG-05).** When a run already has issues, time or output, should it still be cancellable, with a reviewed residual close, or should cancel be refused and "Finish with approved loss" offered instead, with P15 closing the run? Recommendation: refuse cancel once any fact exists, as ERPNext does, and close through approved loss and P15. Cancel stays simple for drafts and unposted released runs.
2. **Actual or provisional costing at close (I-MFG-06).** For a run whose output had no approved standard, should the close's residual go to the output (the on-hand share to asset value, the consumed share to COGS) or to production variance? Recommendation: to the output, by the landed-cost split, under a standard-or-actual basis on the ProductionAllocationPolicy row. Variance stays the rule for standard-costed runs.
3. **Over-consumption (I-MFG-03).** Should an issue beyond a line's remaining quantity be blocked above the tolerance until a supervisor approves, or allowed with a warning at completion (Odoo's "warning" mode)? Recommendation: block above the tolerance with supervisor approval, the same path as overproduction, and list under-consumption at completion.
4. **Method context layer (I-MFG-01).** Should the existing `ironstone.products.MethodServices` serve both contexts, made appRoot-aware, or should Manufacturing get its own wrapper service? Recommendation: one appRoot-aware service, so the shared screens keep one set of transitions and one access rule.
5. **Production approver (I-MFG-11).** If P0 confirms F17, should the Mantle change to `get#TimesheetApprovers` and its ProductionPolicy flag be dropped for the supervisor-as-Manager convention? Recommendation: yes. Keep a flagged change only if both "run supervisor or line manager" approvers are needed at once.
